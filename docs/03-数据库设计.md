# 03 · 数据库设计（SQLite）

数据库文件：`data/foodbox.sqlite3`（已在 `.gitignore` 中忽略，用 `scripts/seed.py` 生成）
建表脚本：`db/schema.sql`

## 约定

- 所有金额以**分**为单位存整数，避免浮点误差，接口返回时再转成元。
- 时间统一用 `TEXT` 存本地时间 `YYYY-MM-DD HH:MM:SS`，取餐时段用 `HH:MM` 字符串。
- 订单状态只有三种：`booked` 待取餐 / `done` 已核销 / `cancelled` 已取消。

## 表一览

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `campuses` | 校区 | id, name, sort |
| `users` | 学生与商家账号 | phone(唯一), role, campus, points, points_all, canteen_id |
| `canteens` | 食堂档口 | name, campus, window, intro |
| `categories` | 餐段 / 品类两级分类树 | parent_id 自引用 |
| `dishes` | 菜品 | canteen_id, category_id, name, emoji |
| `boxes` | 盲盒 | price, original_price, total, remain, pickup_start/end, carbon_g, status |
| `orders` | 订单 | order_no, pickup_code, qty, amount, status, carbon_g, points |
| `carbon_logs` | 碳积分流水 | user_id, order_id, delta, reason |
| `rewards` | 可兑换权益 | points, stock |
| `redemptions` | 兑换记录 | code, used |
| `reviews` | 评价 | order_id(唯一), rating, text |
| `faqs` | 帮助中心 | group_name, question, answer |

## 主要关系

```
campuses ──< canteens ──< boxes ──< orders >── users
                    └──< dishes         │
categories ──< categories(子)           ├──< carbon_logs
   └──< boxes / dishes                  └──< reviews(1:1)
rewards ──< redemptions >── users
```

## 关键字段说明

**`users`**
- `role`：`student` 学生（App / Web 学生端）、`merchant` 商家（后台）
- `points` 当前可用积分，`points_all` 累计获得积分（等级按累计值算）
- `canteen_id` 仅商家有值；商家登录后在所有查询里按该档口过滤数据

**`boxes`**
- `status`：`draft` 未上架 / `active` 在售 / `soldout` 已售罄 / `offline` 已下架
- `remain` 剩余份数：下单时扣减，取消订单时回滚；
  减到 0 时自动置 `soldout`，回滚为正时自动恢复 `active`
- `carbon_g` 每份预计减碳克数，积分按 `carbon_g ÷ 10` 折算

**`orders`**
- `order_no`：`SG` + 日期 + 序号；`pickup_code`：6 位随机数字
- `verified_at` 为空表示尚未核销
- 积分在**核销时**才发放（写入 `carbon_logs` 并更新 `users.points`）

**`carbon_logs`**
- `delta` 正为获得（取餐完成），负为消耗（兑换权益）
- 兑换记录不关联订单（`order_id` 为空）

## 接口与 SQL 的对应

| 接口 | 主要操作 |
| --- | --- |
| `POST /api/orders` | 校验 `status='active' AND remain>0` → 插入订单 → 扣减 `remain` |
| `POST /api/orders/:id/cancel` | 置 `cancelled` → 回滚 `remain` 与 `status` |
| `POST /api/admin/verify` | 校验核销码与档口 → 置 `done` → 发放积分 → 写流水 |
| `POST /api/rewards/:id/redeem` | 校验积分与库存 → 扣积分、扣库存、写兑换记录与流水 |
| `GET /api/admin/overview` | 按日 / 周 / 月分组统计订单数、份数、金额、减碳量 |
